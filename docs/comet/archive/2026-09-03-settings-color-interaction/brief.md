# 目标

降低设置页颜色配置的操作成本。用户能先从六个状态中直接选中目标，再用颜色选择器、HEX 输入或预置色修改该状态；当前状态和当前颜色始终清晰可见。

# 范围

- 仅调整设置页颜色区域的 HTML 结构、CSS 和前端交互。
- 六个状态仍分别使用现有 `<state>_color` 字段；不改变 Rust 持久化合同、默认值、渲染逻辑或保存队列。
- 移除与颜色预置区分离的 `Apply preset to` 下拉框。
- 六个状态行增加直接选择目标的入口和当前颜色预览；用户点击或键盘选择状态后，预置色直接应用到该状态。
- 保留原生 `input[type=color]`、可编辑 `#RRGGBB` 输入、现有 70 个预置色和十组分组展示。
- 每个状态提供恢复该状态默认颜色的操作。
- 状态切换、颜色输入、预置色应用和恢复默认均复用现有 `save_settings`、串行保存队列和 `settings-changed`。
- 保留英文、简体中文、窄窗口回流和现有控件字段 ID；补充必要的 i18n 文本和前端行为测试。

# 非目标

- 不增加主题系统、全局调色板、颜色收藏、拖拽排序、截图导入或预置色管理。
- 不改变状态数量、状态名称、状态优先级、颜色格式、后端合同或光环动画行为。

# 验收示例

- Scenario: 设置页打开后，六个状态都显示名称、当前颜色预览和 HEX 值；当前预置目标有清晰选中状态。
- Scenario: 用户点击或用键盘选择某个状态，再点击任一预置色时，只有该状态颜色改变并触发现有保存同步。
- Scenario: 用户直接编辑某个状态的颜色选择器或 HEX 输入后，该状态自动成为当前预置目标；非法 HEX 不保存。
- Scenario: 用户执行某个状态的恢复默认操作时，只有该状态恢复内置默认色并触发现有保存同步。
- Scenario: 切换 `en` 与 `zh-CN`，颜色区域的状态名称、操作文本和无效输入提示仍正确渲染；桌面和窄窗口均无横向溢出。

# 约束与不变量

- 现有六色字段和 70 个预置值保持不变。
- 不新增并行存储或第二套保存路径。
- 状态选择只影响预置色和恢复默认的目标，不影响 overlay 当前状态。
- 所有新增可操作元素可用键盘访问，并保持清晰焦点样式。

# 决策

- 采用“状态行直接选目标”方案：比单独下拉框少一步，且用户能从当前颜色预览定位目标。
- 保留六行独立编辑控件：避免隐藏现有控件 ID，减少数据同步和回归风险。
- 预置色继续全部可见并按十组分组；不引入折叠、搜索或收藏，避免为 70 个固定值增加额外状态。
