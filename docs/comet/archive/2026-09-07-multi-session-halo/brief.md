# 目标

让同一个 Halo 同时表达多个 Codex 会话的当前状态，各会话的状态变化独立生效。用户原始需求：当前表现只能满足单线程，希望全方位监听多个线程，各线程状态不同时以多色同时呈现。

# 范围

- 复用现有 Hook 输入、按会话隔离的快照文件、目录扫描和 SessionStore。
- 将当前只输出一个主状态的显示数据扩展为可表达多个会话状态的数据，贯通原生查询、事件与光环渲染。
- 颜色继续代表状态并使用现有七项自定义配色；多会话不再只显示最高优先级的一种状态。
- 同一会话更新、结束或快照失效，只影响该会话的显示贡献。运行状态不再因 60 秒无新事件自动移除。
- 采用“游丝共舞”：每个会话对应独立亮芯和渐隐光尾，沿当前数学曲线以轻微错开的节奏游动；同状态会话仍保留各自流光，颜色跟随所属会话状态变化。
- 监听同一个 CODEX_HOME 下已接入并触发本插件 Hook 的会话，包括实际提供独立会话标识和事件的子代理；该范围以外的来源不宣称已覆盖。

# 非目标

- 当前未提出跨设备同步、远程进程监听、任务内容读取或新增会话管理面板。
- 现有输入只能识别 Hook 提供的 session_id；没有独立标识和事件的执行单元不能凭空推断状态。
- 不新增宿主 Hook 能力、跨 CODEX_HOME 汇总、同一 session_id 内部并行工具计数、心跳存活检测或手动清理面板。

# 验收示例

- A1：两个不同会话分别思考和执行时，同一光环同时出现各状态的配置颜色；等待输入的第三个会话出现后，已有两种状态仍可见。
- A2：一个会话从执行切换到完成或结束时，另一个仍在思考的会话保持其状态，不被前者覆盖或清空。
- A3：调整某一状态的配置颜色后，所有处于该状态的显示部分同步更新，其他状态保持自身配色；单会话仍呈现对应状态颜色。
- A4：事件推送与轮询响应交错时，较旧响应不能覆盖已经应用的新显示；非法或无效快照不能破坏其他有效会话状态。
- A5：两个思考中、一个执行中、一个等待输入的会话同时存在时，显示四条独立流光，颜色分别读取 thinking_color、thinking_color、executing_color、input_needed_color；其中一个会话变更状态只改变自身流光颜色。不得硬编码为默认颜色。
- A6：thinking、executing、compacting 会话超过 60 秒没有新事件仍显示最后状态；input_needed 同样保留。重新启动 Halo 后，只要对应合法快照仍在，也继续显示这些最后已知状态；不将其计数描述为经存活探测确认的在线数。
- A7：completed 和 interrupted 在 3 秒保留期内显示各自颜色，超过 3 秒移除；SessionEnd 移除自身流光；idle 继续采用原有 60 秒失效规则。最后一条有效流光移除后显示原有空闲光环。
- A8：重复轮询或改变会话遍历顺序不交换流光的会话身份；新增、移除和切换状态不重置其他流光动画。2、4、13 个有效会话均逐一呈现，不按状态合并或静默截断。
- A9：状态模拟暂时呈现模拟颜色，不修改真实会话集合或增加真实会话计数；模拟结束后恢复完整多会话流光。关闭动画偏好时仍同时呈现各条流光的状态颜色。
- A10：多会话采用独立亮芯与渐隐细尾，流动节奏轻微错开且不随机跳位或无界追尾；换状态时新配置颜色从亮芯沿尾部传播，并在 420ms 内完成。新线程从短光芽展开；完成或中断在原有 3 秒反馈期末收束淡出。增多至 13 线程时缩短尾迹、收敛光晕，保留各亮芯和可见暗隙；降低动态效果时保持静态多色辨识。

# 约束与不变量

- 不记录 prompt、transcript、工具内容或原始 session_id；复用现有匿名 session_key。
- 复用现有数学曲线、动画参数、位置、透明度、420ms 颜色过渡和 reduced motion 行为；多条流光共享当前曲线，使用独立位置和必要的尾迹长度适配以避免完全重叠，不增加多个悬浮窗口。
- 保留 completed/interrupted 超过 3 秒失效、idle 超过 60 秒失效及 input_needed 不按时间失效；thinking/executing/compacting 改为保留最后状态直到后续事件更新或会话结束。
- 无心跳或存活探测；显示及计数表达最后已知状态。异常退出、丢失结束事件可能残留流光，旧的合法运行快照在重启后也可能重新出现；这是用户选择持续保留的明确限制。
- 当前监听限于 Halo 使用的状态目录和实际到达的 Hook 事件；子代理是否提供独立 session_id 需按真实事件能力核实，不宣称已完成全来源覆盖。

# 决策

- 已确认需求：多个会话的不同状态同时以多色呈现。
- 调查结论：现有采集按 session_id 哈希分别存储；reduce_snapshots 按状态优先级、再按时间选出单个 state；DisplayState 和前端 renderer 均只消费一种状态颜色。
- 用户已选择：每线程一条独立流光，同状态不合并；颜色完全读取用户在设置中保存的状态配色。此前橙、橙、蓝、红仅是默认配色示例，不是固定规则。
- 用户已选择：运行中会话超过 60 秒无事件仍保留最后状态，收到完成、中断或结束事件后退出；用户知悉异常退出且丢失结束事件时可能残留。
- 完成和中断保留现有 3 秒反馈，结束事件直接移除；空闲继续采用现有有效期。持久化仍复用快照，重启恢复受同一有效期规则约束。
- 保留单状态摘要字段供现有设置和诊断消费者兼容使用，桌面光环使用完整会话集合绘制；不新增配置项或依赖。
- 使用一个 Native change；数据契约与渲染紧密耦合，无需拆成独立子 change。
- 用户已明确选择第一种“游丝共舞”：独立亮芯、渐隐光尾、有界错相节奏与暗隙，状态颜色从亮芯沿尾部传递。新线程从短光芽展开，完成或中断在原有反馈期末收束淡出；不增加其他视觉模式或模式选择控件。
- 设计评估优先检查约 112px 的实际尺寸、同色多线程、13 线程密度、曲线交叉、明暗背景及减少动态效果。光芯保留配置颜色，不靠叠色冲白或任意改色制造层次。

# 待解决问题

- 无。用户已确认配色、监听有效期、游丝共舞动势及完整实施范围。

# 验证预期

- Rust：多会话完整输出、单会话更新/移除、终态与空闲失效边界、超过 60 秒运行状态和持久快照恢复、模拟状态隔离；复用现有测试设施。
- JavaScript：完整显示数据传递、乱序轮询保护、稳定流光身份、混合颜色与动态自定义配色；沿用 node:test 和现有 renderer 检查。
- 浏览器视觉检查：单会话和 2、4、13 会话，至少覆盖默认曲线、闭合曲线及开放曲线；确认多色可辨认性、增减状态过渡和 reduced motion。
- 实现与验收进度以 Runtime 状态和验证报告为准，本说明保留已确认的需求及验证要求。
