# 目标

把现有 Codex Halo 设置页从“面板堆叠”改为可扫描的设置工作台，重点改善界面美观性、交互友好性和布局合理性。保留现有设置能力、自动保存、双语、Tauri IPC 与 Plugin/诊断行为。

# 范围

- 页面结构：改为桌面双栏工作台。左侧为轻量分区导航，右侧为设置内容；首屏优先显示叠加层开关、显示参数和渲染参数。
- 信息层级：将现有内容归为「显示」「动画」「状态颜色」「集成」「测试」五个语义区；诊断信息与集成操作靠近，运行时开关不再埋在页面最底部。
- 状态颜色：保留六个状态、颜色选择器、Hex 输入、恢复默认和预置色；交互改为先选状态，再编辑当前状态，预置色库默认收起，减少长页面。
- 视觉系统：保留深色 graphite 基底、Codex Halo 的暖橙强调色和状态色；减少厚重阴影，强化标题、分组、当前状态和操作反馈的层级；控件保持原生 HTML/CSS。
- 交互反馈：保留即时自动保存；增加低干扰的保存中/已保存/失败状态反馈。控件 hover、focus、active、disabled、loading 和 error 状态统一。
- 响应式：桌面设置窗口建议调整为约 `960×760`；宽屏使用双栏，窄于 `880px` 时导航折叠为横向分区条，内容回流为单列；不得出现横向滚动、文字遮挡或焦点丢失。
- 目标文件：`src/settings.html`、`src/settings.js`、`src/styles.css`、`src/i18n.js`，以及仅用于调整设置窗口默认尺寸的 `src-tauri/src/main.rs`；必要的现有前端测试同步更新。

# 非目标

- 不改 `AppSettings` 字段、范围、settings JSON、IPC command、事件名称或保存事务。
- 不改 Overlay 渲染算法、Plugin hook、托盘菜单、原生 helper 和其他页面。
- 不新增 UI 框架、图标依赖、第三方组件库或实时 Halo 预览；预览属于后续独立功能。
- 不把设置拆成多个窗口，不引入需要额外状态持久化的 Tab/路由系统。

# 验收示例

- A1: 在约 `960×760` 的桌面窗口中，首屏可同时看到产品标题、Overlay 开关、显示参数和渲染参数；页面不再以大量同权重面板开场。
- A2: 桌面设置页存在清晰的分区导航；点击分区后，内容滚动到对应区域，键盘顺序仍按内容语义递进。
- A3: 状态颜色区默认只突出当前选中状态；切换六个状态时，当前颜色编辑器、预览和 Hex 值同步切换，六个颜色字段仍全部可读写。
- A4: 预置色库可展开和收起；选择预置色、修改颜色、恢复默认均复用现有保存路径，不产生重复保存或错误覆盖。
- A5: 修改任意设置时，界面显示低干扰的保存反馈；保存失败时保留现有诊断错误展示，且不吞掉错误。
- A6: 切换 `en` 与 `zh-CN` 后，标题、导航、标签、按钮、状态、诊断和预置色文本自然换行，布局不破坏。
- A7: 在窄于 `880px` 的视口中，导航和内容回流为单列；所有控件、按钮、公式和诊断文本不横向溢出、不重叠。
- A8: 现有控件 ID、`name`、`data-i18n`、`data-state`、`data-color-*` 契约保持可用；插件安装/卸载、诊断导出、重置位置、状态模拟和自动保存行为不变。

# 约束与不变量

- 设置页是 Operate（操作型工具）界面：扫描效率、状态反馈、键盘可达性优先于装饰。
- 继续使用原生 HTML/CSS/JavaScript 和现有深色视觉基调；卡片圆角不超过 `8px`，不使用渐变背景、装饰性光球或大面积阴影。
- 继续保留现有 `settings.js` 依赖的所有控件 ID 和数据属性；DOM 顺序与焦点顺序保持一致，不用 CSS 视觉重排制造反向阅读顺序。
- 固定格式控件使用稳定尺寸；英文、简体中文、失败状态和长公式允许自然换行。
- 不改变后端字段校验、颜色规范化、Tauri command 及事件契约。

# 决策

- 采用「Halo Control Room」工作台方向：窄分区导航 + 内容工作区 + 明确的首屏核心设置。
- 桌面默认窗口采用约 `960×760`，换取颜色与高级参数的可读宽度；`880px` 以下回流为单列。
- 颜色编辑采用“状态选择器 + 单一活动编辑器 + 可折叠预置色库”；保留所有字段和键盘可达性。
- 保留自动保存，不增加主 Save 按钮；新增的只是保存状态反馈。
- 不加入实时预览；现有公式、诊断状态和状态模拟作为当前页面的反馈证据。
- 用户已通过 Visual Companion 选择 `A · Halo Control Room`。
