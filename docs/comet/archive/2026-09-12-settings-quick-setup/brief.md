# Outcome

面向“快速配置后长期使用”的 Codex Halo 用户，重新设计设置菜单的产品结构、交互、布局与样式。核心任务是选好效果、确认接入、放心关闭设置；用户明确接受完全重构，不受现有四页结构约束。

# Scope

## 已确认范围

- 对现有设置菜单进行产品层面的整体重构，涵盖交互、布局和样式。
- 以低频配置、长期可靠使用为主，保留深入调整现有光环效果的能力。
- 使用独立 Native change `settings-quick-setup`；旧 change 的归档记录保持原样。

## 已确认方案

- 一级入口收敛为“光环”和“连接与运行”；光环页完成选方案、看效果、微调和状态配色，连接与运行页处理接入、启动行为及排障。
- 预览靠近当前编辑控件；状态选择、配色与效果验证形成连续操作，不再依靠独立测试页完成日常调色。
- 常用控制直接可见，曲线精细参数及公式按需展开；保留曲线、动画、七种状态颜色、音频响应、插件管理、诊断和运行设置。
- 设置内模拟与真实桌面任务状态分离；自动保存提供明确结果及失败重试；加载方案明确覆盖范围，提供恢复切换前外观的能力。
- 接入信息仅表达可观测事实，不把无新事件等同断连，不把模拟成功等同真实接入成功。
- 用户在阅读本需求后明确回复“确认”；上述产品方向作为本轮实施范围，以下边界将其收敛为可验证行为。

## 实施边界

- 复用现有深灰、暖橙与系统字体，重做信息结构和布局；宽窗预览与编辑并排，窄窗让预览紧邻控件；不新增主题系统。
- 默认打开光环。连接与运行提供准确的接入说明、现有插件操作及诊断结果，不新增后台插件探测或依据无事件自动重定向。
- 七状态本地预览不调用 `simulate_state`；原桌面测试移到连接与运行的高级诊断，明确会改变桌面模拟状态，沿用原有事件及失效规则。
- 曲线浏览和聚焦仅预览，显式加载仍应用该曲线的几何及六项动画默认值。一次恢复仅覆盖 `curve_id`、`curve_parameters`、`particle_count`、`trail_span`、`duration_ms`、`pulse_duration_ms`、`rotation_duration_ms`、`stroke_width`；不覆盖颜色、透明度、发光、位置、语言或音频。外部相关值发生变化后，使旧恢复记录失效；关闭窗口后不持久化恢复历史。
- 保存重试写入当前最新合法设置，不保存非法颜色草稿。预览状态、展开折叠、导航等纯界面操作不触发配置保存。

# Non-goals

- 不以高频创作工作室为产品定位；本轮不引入作品库、收藏、版本管理、云同步或多方案比较。
- 不为新需求修复、覆盖或删除旧 change 的归档。
- 不默认更换技术栈、重写真实任务状态归并或改变插件权限及数据收集边界。

# Acceptance examples

以下为用户确认方向的任务级验收，详细场景由完整目标规格补充。

- A1：用户能在同一光环配置页面完成选择状态、修改该状态颜色和查看效果，无需切换一级页面。
- A2：用户能区分设置内模拟与真实桌面状态；仅操作本地预览不会覆盖真实任务显示。
- A3：用户加载曲线方案前能理解替换范围，并能恢复切换前的外观配置。
- A4：用户修改后能识别保存中、保存成功或失败；失败时保留最新编辑并可重试。
- A5：连接与运行页面准确区分可观测的安装、事件及运行信息，并为已知问题提供对应下一步。
- A6：现有功能在中英文、默认及窄窗、键盘操作和减少动态效果条件下均保持可达，页面无横向溢出。

# Constraints and invariants

- 当前目录为 `D:\Projects\codex-math-curve-halo`，沿用 `main`；创建前工作区干净。
- 兼容现有配置、参数精度、串行保存、部分事件合并和编辑保护；界面重排不能丢失未挂载值或用户输入。
- 当前测试命令会修改桌面模拟状态；本地预览必须明确与该命令分离，不能只更改入口名称。
- 当前运行模型表示最后已知事件状态，不构成存活探测；连接文案不得超出证据。
- 设置页视觉不污染透明桌面光环；保留中英文、键盘可达、可见焦点和减少动态效果支持。
- 旧规格中的四页导航、禁止常驻预览、公式常显和测试页语义属于本轮待替换条款，不能同时作为新方案的不变量。

# Decisions

- 用户明确允许设置菜单完全重构，并要求从产品经理视角重新审视。
- 用户明确选择“快速配置后长期使用”，排除以持续视觉创作为主要任务的产品定位。
- 用户明确要求新开 change；采用新名称 `settings-quick-setup`，不继续处理旧 `settings-layout-redesign` 的恢复问题。
- 用户在需求文档建立后明确回复“确认”，接受本轮产品方向；边界采用现有能力和最小实现，不引入创作工作室、额外检测服务或新配置协议。
- 当前采用单个普通 Native change。设置壳层、预览、配色、保存和国际化高度共享，拆成独立子 change 会重复修改核心区域。

# Verification expectations

- 先建立现有功能与受影响完整目标规格的覆盖映射，再形成最终 Shape 确认摘要。
- 对本地预览与真实状态隔离、方案恢复、保存失败重试及外部事件并发进行行为验证。
- 使用浏览器检查两页完整流程、默认及窄窗、中英文、键盘与错误状态；静态浏览器无原生接口时，不将模拟接口结果当作原生验收。
- 原生插件、启动行为、音频和真实状态链路按实际平台验证，并明确未运行的检查。
