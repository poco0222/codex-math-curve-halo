# 多会话状态显示

本规格描述完整目标：每主线程家族独立流光、子代理内嵌色段、运行状态持续保留和“游丝共舞”动势。

## 会话状态来源

Halo 使用现有 Hook 事件和按匿名 session_key 隔离的快照维护会话状态。不同 session_key 的有效状态必须独立保留。会话更新、结束或快照失效只影响对应会话，不得清空其他有效会话。

有效状态包括 idle、thinking、executing、input_needed、completed、interrupted、compacting。事件输入保持现有验证与隐私约束，不读取会话内容补推状态。

同一个 CODEX_HOME 下、Halo 当前状态目录中收到本插件 Hook 的会话属于可观察范围。SubagentStart 和 SubagentStop 使用 session_id 标识所属会话、agent_id 区分子代理。子事件缺失或带空白 agent_id 时拒绝，不能回退写入父状态。其他现有事件若明确提供有效 agent_id，则更新对应子状态；否则保持会话级语义，不推测子代理身份。没有事件的来源不能被当作已成功监听。

数据模型保留匿名会话键、状态和更新时间，子快照额外保留可选匿名父会话键。旧快照不要求新增字段，父会话原有键不变。沿用现有输入验证和隐私边界，不新增 prompt、路径、工具数据、原始 session_id 或 agent_id。非法快照不影响其他有效会话。每次查询提供完整父子集合，session_count 表达有效主线程家族数；既有兼容摘要字段仍可用于设置和诊断，桌面光环不得只消费摘要。

## 同时表达

桌面光环必须能同时表达多个有效会话的不同状态。最高优先级会话不得遮蔽其他有效会话的全部状态表达。查询与事件必须传递足以呈现多会话的数据；前端不得再次缩减为单个主状态。

颜色语义沿用完整 State Color Configuration 规格：颜色代表状态，采用对应的七个 <state>_color 字段，缺失或无效前端颜色值使用该状态默认值。修改状态颜色必须同步作用于所有相应状态的显示贡献。

一个会话有效时显示其状态颜色；多个会话全部无效或结束后回到现有空闲表现。已有单状态模拟暂时呈现对应模拟颜色，不改写真实会话集合或增加真实会话计数；模拟结束后恢复完整多会话显示。

## 更新一致性

同一会话的新状态不得影响其他会话的状态。状态事件和轮询结果必须使用现有新旧请求保护原则，过时响应不得回滚较新显示。单个非法快照不能使其他有效会话失去显示。

稳定会话标识用于持续关联同一条流光；HashMap 或文件遍历顺序变化不改变会话身份。真实状态变化只更新所属流光，不能重置其他流光的动画相位。颜色状态变化沿用 420ms 过渡；设置颜色变化同步更新对应状态的全部流光。

## 每线程独立流光

- 每个有效主线程家族在同一数学光环上对应一条独立流光。只有主线程占用独立主头和运动位置；所属子代理在这条尾迹内部表达状态。
- 同状态的多个会话保留各自流光，不合并成按状态计数的颜色区域。
- 两个思考中、一个执行中、一个等待输入的会话对应四条流光，颜色依次取 thinking_color、thinking_color、executing_color、input_needed_color，不硬编码默认配色。
- 同一会话的流光身份在轮询之间保持稳定，不因 HashMap 遍历顺序变化跳到其他会话的位置；新增、结束和状态变化分别作用于对应会话。
- 继续使用当前数学曲线，流光在该曲线上分布，以独立位置和随数量适配的尾迹长度避免所有流光完全重叠；曲线轮廓、几何参数和运动设置继续生效，不新增悬浮窗口。
- 所有有效会话都进入渲染集合，不按状态合并、不静默截断。至少以 2、4、13 会话检查可辨认性；会话非常多时允许视觉密度增加，不承诺仅凭颜色辨认任务名称。
- reduced motion 下停止既有运动，仍同时呈现各会话的静态状态颜色；沿用现有设置中本地化状态名称、颜色编辑和焦点可访问性，不用多色替代这些文字信息。

## 子代理内嵌色段

- 同一匿名父会话键的子快照归入同一家族。主头及靠近头部的连续区段保留父状态色，子状态分布在尾迹内部，颜色交界柔和且轮廓连续，不产生额外亮芯或独立空间运动。
- 子代理启动以 thinking 表达最后已知活动，停止以 completed 表达停止反馈，完成态沿用 3 秒有效期。它们不证明工具级精细状态；只有可明确归属的事件才更新相应状态。
- 所有有效子状态按稳定身份排序进入色段；同色仍保留独立数据身份，不按颜色合并或静默截断。子代理增减、状态变化、轮询重排不得改变主头身份、主线程间距或其他家族运动位置。色段可在家族内部重新分配范围，沿用不超过 420ms 的连续颜色过渡。
- 主状态完成或中断后，只要仍有有效子状态，保留父状态作为主头上下文和该家族流线。主头不得先消失、将子代理误显示成独立主线程；最后一个子状态失效后按父状态现有期限退出。
- 只收到子快照、没有可用父快照时，按匿名父键组成家族，以 idle 作为未知父上下文的中性回退；不推断父线程处于 thinking、completed 等状态。
- 用户修改状态配色时，主头和相应子色段同时采用新配置色。减少动态效果时停下空间运动，保持静态父子状态。
- 颜色不作平均混合，边界过渡之外保留状态色。大量子代理或小尺寸下允许辨识度下降，不承诺仅凭光环读出精确数量、名称或每个代理状态；不添加数字标签、独立窗口或新设置。

## 游丝共舞的视觉编排

外观动画设置提供“光晕”开关，对应 glow_enabled 布尔字段，默认 false；旧配置缺少字段时同样关闭。关闭时仅绘制曲线轮廓、渐隐主体与亮芯；开启时恢复既有外围宽幅透明光晕。切换立即生效且不重置动画相位，复用自动保存与设置事件，重挂载及重新加载后保持；非布尔值沿用配置校验拒绝。无会话时既有空闲表现不受此开关影响。

- 曲线轮廓直接使用配置 stroke_width；流光主体不再乘 0.44 或限制到 2.4，恢复厚实程度，尾部仍渐隐；1、4 会话保留配置厚度，更多会话允许必要的密度适配。
- 每条流光由清晰的亮芯和逐渐消隐的光尾组成。保留当前数学曲线轮廓，利用沿线位置、尾迹疏密和暗隙区分线程；不使用固定色块分区、整圈彩虹或多根完整曲线叠加替代独立流光。
- 在线程稳定身份的基础上，使用幅度受限的节奏差异表现轻微缓急变化；不使用无界随机速度，不因轮询重新抽取位置或相位。新增和退出不得重置其他线程的连续运动。
- 状态变化时，新颜色从亮芯沿尾迹传递，在既有 420ms 内完成到新配置色的过渡。高频状态变化从当时实际显示颜色继续过渡，不重放历史颜色。亮芯目标色严格取当前状态配置，外围光晕仅在 glow_enabled 为 true 时绘制，不强制改为白色或另设审美调色板。
- 新线程从短光芽平滑展开，进入展开不晚于 420ms 完成；完成和中断先保留配置颜色反馈，再在已有 3 秒有效期末收束淡出，不延长终态有效期。SessionEnd 仍直接移除，不额外保留代表存活线程的光芯。
- 线程增多时缩短各光尾、适配主体宽度以控制密度，保留全部线程独立亮芯；同色线程仍通过暗隙和位置分离。不得通过合并同状态、丢弃线程或叠色冲白减少视觉密度。
- 设计验收同时观察约 112px 实际尺寸和放大细节；至少覆盖 2、4、13 线程、全部同色、明暗背景及曲线交叉。减少动态效果时停止空间游动与呼吸，保留静态多色与状态反馈。

## 持续监听与退出

- thinking、executing、compacting 不因 60 秒无新事件失效，持续显示最后收到的状态，直到同会话后续事件更新或结束。
- input_needed 保持现有不按时间失效的规则。
- completed、interrupted 从对应事件时间起保留现有 3 秒反馈，超过 3 秒后移除。保留期内收到新状态时，同一身份转为新状态；父快照作为仍有效子状态的上下文时按上节保留。
- idle 保持现有 60 秒失效规则，边界时刻仍有效。
- 父 SessionEnd 删除对应父快照及其子快照，移除家族流光；其他家族保持。子身份的移除只影响该子快照。父 Stop 仅更新父状态，不清空仍在工作的子代理。宿主不对子代理发射 Interrupt 或 SessionEnd 的场景，不伪造相应事件。
- Halo 每次进程启动记录时间边界，初始为空闲；仅接收事件时间晚于启动边界的合法快照，启动前及同毫秒的历史快照不贡献流光和计数。边界在首次扫描之前固定，首次扫描期间到达的新事件正常接收；重复扫描不能复活历史记录。此规则不删除磁盘快照。
- 启动前已运行的任务须等待下一次事件才显示。本次启动后接收的状态继续使用既有有效期规则；下一次重启重新等待新事件。未来时间戳和非法快照维持既有拒绝规则。
- 不引入心跳或会话存活探测。界面表达最后已知状态，计数表达被保留的有效状态记录数量，不能声称是已确认存活的在线线程数。本次运行期间丢失结束事件仍可能残留流光；重启后不恢复这些旧记录，不把启动过滤等同于真实存活检测。

## 范围与兼容

复用现有 Rust/serde、Tauri 查询与事件、vanilla JavaScript、Canvas、曲线和设置存储，不增加运行依赖；仅新增默认关闭的 glow_enabled 配置项。保留单状态摘要对既有消费者的兼容性。状态颜色的所有配置语义继续由既有 State Color Configuration 规格约束。

不新增跨设备或跨 CODEX_HOME 汇总、宿主 Hook 能力、任务内容读取、缺少 agent_id 的并行工具追踪、手动会话管理或残留清理面板，也不承诺事件源没有提供的顺序和身份信息。真实宿主发射、安装版和 Windows 验证须与受控事件测试区分记录。
